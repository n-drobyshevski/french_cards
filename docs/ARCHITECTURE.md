# Карточки для Лизи: architecture and conventions

Read with `docs/plan.md` (scope and phases), `mockups/SPEC.md` (the v3 visual design: tokens, components, copy rules and every screen) and the mockup sources in `mockups/*.dc.html`. The mockups are the visual source of truth: match their layout, spacing, copy and states.

## Stack
- **App:** Next.js 16.4 App Router + Turbopack, React 19.3, TypeScript, Tailwind 4.
  - This Next is newer than most training data. Read `node_modules/next/dist/docs/` before using an API you're unsure of.
  - `cacheComponents: true` is on.
  - Request interception lives in `proxy.ts` (the old `middleware.ts` was renamed).
- **Data:** Dexie 4 (`lib/db.ts`) is the on-device source of truth. The UI reads it with `useLiveQuery` from `dexie-react-hooks`, so screens that use it are client components (`"use client"`).
- **Scheduling:** `ts-fsrs@5`, used only through `lib/scheduler.ts`.
- **Sync and auth:** Supabase (`@supabase/ssr` + `@supabase/supabase-js`).
  - Login is email + password (works inside the iOS home-screen app and needs no custom SMTP); any Supabase account may sign in (sign-up stays off; each account has its own library through RLS), and only the addresses in `ALLOWED_EMAIL` (comma-separated) may use the AI routes. With several addresses in `NEXT_PUBLIC_ALLOWED_EMAIL` the login screen prefills none. Password reset links land on `/auth/confirm` → `/auth/reset`.
  - Sync is last-write-wins on `updated_at` with soft deletes (`deleted_at`). `review_log` rows are only ever soft-deleted (undo).
- **AI:**
  - Packages: `ai@7`, `@ai-sdk/anthropic@4`, `zod@4`.
  - Model `claude-haiku-5-5`; «Точнее» is `claude-sonnet-5-5`. Provider options come from `providerOptionsFor(modelId)` (`lib/ai/model.ts`), chosen by the resolved model id: Haiku gets `thinking: {type:'disabled'}`; Sonnet 5.5 rejects `disabled`, so it gets `thinking: {type:'between_tools'}` with `effort: 'medium'` (faster than its default high, without trimming «Точнее» answers). Keep them fixed per model (a changed effort breaks the prompt cache). Never set temperature/top_p/top_k and never prefill.
  - Use `streamText`/`generateText` with `output: Output.object|array(...)`.
  - Schemas: no `.min/.max/.length`, every field required (use `.nullable()`), confidence is an enum. Limits go in `.describe()` text, and results are sliced on the server.
  - The v7 API changed (`instructions`, `type:'file'` image parts, `Output`). Read the typings in `node_modules/ai` and `node_modules/@ai-sdk/anthropic` before writing calls.
- **PWA:** `app/manifest.ts` + Serwist via `@serwist/turbopack`.

## Product rules
- UI copy is Russian; words are French.
- Never show «ИИ»/«AI», sparkles or "magic" in the UI. The one exception is Settings: the section «ИИ» and its privacy line.
- Settings «ИИ» (device-local, `lib/types.ts` `Settings`): «Автоподсказки при вводе», «Определять уровень сленга», «Подбирать примеры», «Раскладывать по темам автоматически», «Писать заметки», «Вариантов» (1–3), «Регистр вариантов» (сленг / любой / нейтр.), «Модель: подсказки» and «Модель: скриншоты» (Быстрее = Haiku 5.5, Точнее = Sonnet 5.5). Clients send a tier (`model: "fast"|"accurate"`), never a model id; preferences go into the user message, so the system prompts stay frozen.
- Every word has `slang_level` 0..3 (нейтр./fam./arg./vulg.) and a `verlan` flag. Show it with the `SlangMeter` component.
- Dictionary abbreviations (n. m., v. pron., loc., fam., arg., verl.…) explain themselves on a tap with `AbbrHint` (glossary in `lib/abbr.ts`; `SlangMeter hints`) wherever they are not inside another button: the word sheet, the answer side of the review card and the add form's headword.
  - The level, an example and a theme are detected for every new word, not only picked suggestions: `/api/ai/enrich` fills the manual form and «Список» rows before saving (fields the user set by hand, including a chosen theme, are never overwritten), screenshot rows carry an example, and the quick one-line save fills them right after saving (`fillSavedWords`, skipped if the word was edited or undone meanwhile). Each part follows its own switch in Settings «ИИ».
  - Themes follow «Раскладывать по темам автоматически». In the form the pick works like a suggestion's (alternatives, «+ новая тема»). «Список» defaults to «По темам автоматически»: each row goes to its own theme, a new theme only when ≥3 rows share it, low confidence stays in «Входящие». After a quick save the word only moves from «Входящие» into an existing theme, never a new one.
  - «Дополнить карточки» in the library proposes examples for words without one and levels for hand-typed words still at the default, applied only after review, with undo.
- Folders («темы») hold words. `folder_id = null` means «Входящие» (Inbox).
  - Библиотека on phones (layout «C · Под пальцем», chosen 2026-10-22): a ledger strip «158 слов / 23 к повт. / 9 трудных» whose cells are also quick filters, a KPI row under it «120 повторено / 14 сегодня» (`FolderStats.reviewed`: words with a non-new card, paused ones included; words graded since the study day began — `FolderStats.reviewedToday`, counts only, not filters; the desktop subline appends the same «· 120 повторено · 14 сегодня»), a dashed «Входящие · N без темы — Разложить» row while something is unsorted, theme tiles that preview their three newest words, and the search with a «Фильтр и порядок» sheet (status, slang levels, theme, order) pinned at the bottom above the tab bar, riding on the keyboard while typing. Two views, remembered per device (`settings.library_view`): «Темы» (tiles) and «Все слова» (one list, «Показать ещё» per 200). A search or filter always shows the matching words; the order alone does not leave the tiles until «Показать». «Разложить по темам» (when nothing is unsorted), «Дополнить карточки» and the last re-sort's «Отменить» are quiet rows under the tiles. A long press on a theme tile (or Android's / the keyboard's context menu) opens the theme's actions instead of the theme: «Открыть тему», «Повторить тему» (when cards are due), «Тренировка всей темы», «Название, описание и цвет», «Закрепить тему», «Расформировать», «Удалить тему» (with undo) — the same `FolderMenuSheet` as «⋯» on the theme screen.
  - «Тренировка всей темы» (theme menus, and the theme screen's bottom button when nothing is due): `/?folder=<id>&practice=1` opens review straight into a practice round over every card of the theme, shuffled, capped at 200 (`buildPracticeQueue` scope «all»); like the other practice rounds it never writes to the schedule.
  - Buttons that call Claude carry the ink spark glyph (`spark`, `spark-refresh`, `spark-plus` in components/ui/Icons): word refresh, examples ↻ / «+», «Разложить», «Дополнить карточки», «Расформировать», «Распознать заново». Nothing else uses it.
  - Examples: a word has up to 5 (`lib/examples.ts`); the first stays in `example_fr` / `example_ru` (review card, Claude connector, older devices), the rest in `extra_examples` (jsonb, migration `0003_extra_examples.sql`, synced). `ExampleList` (components/examples) shows them with «другой пример» ↻ on each and «+ Ещё пример» under them; both ask `POST /api/ai/example` (card + the examples to avoid → one new sentence, null when nothing new fits). In the word's view they save at once with «Отменить»; in the add form and the edit forms they fill the fields (offline «+» adds an empty example to type). The review card shows the first two.
  - «Изменить карточку» (Повторение; mockups: canvas «Повторение — правка карточки», option A): a pencil on the answer side (and `E`) opens `WordDetailSheet` over the review screen; the card re-reads the word live (`getWord`), so edits show at once, practice rounds included, and nothing is graded. The word's entry form proposes a translation by itself (`components/library/translation-proposal.ts`: `useSuggest` with one answer, no notes, «Вариант … Подставить», never filled without a tap), in the sheet and the desktop pane alike.
  - «На паузу» and «Удалить слово» (Повторение, answer side, before the pencil): the trash soft-deletes the word, the struck bell sets `words.muted` (migration 0009, synced); either takes the card out at once (a practice round drops it, history included) with «Отменить». A muted word stays in the library but `matchWords` (lib/session.ts) leaves it out of every session, practice round and count; library rows say «на паузе», the stats and filters count it apart («На паузе» in the phone filter sheet and the desktop strip, only when there is one), and the word card shows «На паузе — не показывается в повторениях · Вернуть» under «Повторение», «На паузу» among its actions. The connector reads `muted` and sets it with `update_word`.
  - «Мои наборы» (Повторение, the «Что повторять» picker; mockups: canvas «Повторение — свой набор», option C): named card sets built from themes (several, «Входящие» included; none = all), word statuses (new / learning / difficult / known), slang levels, age (week / month) and a mode — «По расписанию» (only due + new cards, graded as usual) or «Тренировка» (every card, shuffled, the schedule untouched; picking the set opens straight into the round). Rows of the synced `review_sets` table (migration `0004_review_sets.sql`; soft deletes, last write wins like other rows, so every device sees the same sets; in the JSON backup). Sets stored the old way in `settings.review_sets` move into the table on the Dexie v2 upgrade (`legacyReviewSets`), and old backups are converted on import; the review filter names a set as `set:<id>`; `setSessionFilter` turns a set into a `SessionFilter` (`folderIds`, `slang`, `statuses`, `addedSince`) that `loadSession`, practice rounds and the done screen all honour.
  - «Свои поля» (mockups SPEC/DESKTOP-SPEC «Свои поля»): shared definitions in the synced `field_defs` table, edited in Settings (`components/settings/CustomFieldsSection.tsx`), values on the word in `custom_fields` (`lib/custom-fields.ts`, pure helpers in `lib/core/custom-fields.ts`); filled in the word's view (`components/library/word-fields.ts` + the `fields` part of `word-editor.ts`) and the add form (`WordDraft.customFields`), shown on the review card's answer side (up to 3, `fieldsForDisplay`); deleting a definition leaves its values on the words as one-off fields.
  - «Контекст» (4th tab on phones between «Добавить» and «Библиотека», sidebar/rail item and `G C` on desktop; mockups: canvas «Контекст — мокапы», phone layout B «Досье» with A's sense chips): look up any French or Russian word the way Reverso Context does, spending as little on the API as possible. `POST /api/ai/lookup` (Haiku, cheap) answers with the headword, translations by share and synonyms by register. The conjugation is the word's own `conjugation` when the chat saved one through the connector (`words.conjugation`, migration 0008), otherwise built on the device, never by the app's model: rules for regular -er / second-group -ir verbs plus a table of the others built from Lexique 3.83 (`lib/core/conjugate.ts`, `lib/conjugation.ts`, `scripts/build-conjugation.mjs` → `public/lexique/fr-conj.json`). Example sentences come first from Tatoeba (`lib/tatoeba.ts`, its public API asked from the browser, French sentences with a Russian translation, CC BY 2.0 FR, credited under the list) at no cost; the paid web search (`POST /api/ai/context`: Anthropic web search with up to 3 searches, then a structuring call over the cited snippets; the server keeps a sentence only when it is a verbatim part of a snippet the search cited, with that page's URL, `lib/ai/context.ts`) runs only on «Искать ещё в вебе» (or «Искать в вебе» when Tatoeba has nothing). Queries and their results live in the device-local `lookups` table (Dexie v4, never synced or backed up, 50 newest): the history opens offline and a repeat query costs nothing (`lib/context.ts`, «Искать заново» to refresh); each «Недавние» row has «×» (on desktop shown on hover) with «Отменить», and «Очистить» clears them all. Origin visibility: library rows and the review card's answer side show `word.origin` unless Settings → «Оформление» → «Происхождение слов» is off (`settings.origin_visible`, `lib/use-show-origin.ts`). In the word card «+ Поле» asks which field to add: «Происхождение» while the word has none, «Спряжение» for a verb with neither its own nor a dictionary conjugation, and «Своё поле»; an empty origin or conjugation field is not shown (`addableKinds` in `components/library/WordDetailBody.tsx`). Both forms have «Заполнить автоматически» (`components/library/AutoFill.tsx`, `lib/autofill.ts`): the origin from the «Контекст» history when the word was looked up, else `POST /api/ai/fill` (Haiku, one short call, rate bucket `fill`); the conjugation from `/api/ai/fill` only for a verb the dictionary does not conjugate. It fills the form; nothing is saved until «Сохранить». «Слово по частям» in the word card (desktop: top of the right rail): how the word is made, from Lexique's morphology column on the device («volonté + -aire „относящийся к …“», the root opens in «Контекст»; `scripts/build-morpho.mjs` → `public/lexique/fr-morpho.json`, affix glosses in `lib/core/affixes.ts`, `lib/morpho.ts`), the one-line origin («верлан от lourd», «из арабского kif»: the word's own `origin` when the chat saved one through the connector, else the lookup's), and «Однокоренные» chips. An example goes into the saved word's examples (up to 5) or, for an unsaved word, into the prefilled add sheet; a synonym's «+» opens the add sheet too. Entry points: «Примеры из жизни ›» next to the word's examples, a row under «Варианты» in the add sheet, and a row when a library search finds nothing.
  - «Расформировать» (phone menu, desktop theme menu «Расформировать…»): the classify assign pass picks another existing theme for every word of the theme — hand-placed ones too, since the theme goes away; INBOX or low confidence → «Входящие»; no new themes. The plan (`DisbandSheet`) lets any word be retargeted; applying deletes the theme and moves the words in one transaction (`disbandFolder`), undone with `restoreFolder` (words the user moved since stay put). Without suggestions (offline, error) «Всё во «Входящие»» still works.
  - Automatic sorting never moves a word whose `folder_source = 'user'`, and never renames or deletes a `locked` or user-created folder.
  - A new automatic folder needs ≥3 words.
  - Slang level is never a folder.
- Each word has a review state per direction: `fr_ru`, plus `ru_fr` when `both_directions`.
- Review sessions end («Готово на сегодня»). «Ещё практика» runs extra rounds that do NOT change scheduling.
- Grades: Не знаю = Again, Сложно = Hard, Знаю = Good.
- Nothing produced automatically (suggestions, screenshot rows, sort plans) is saved without the user confirming it. Every bulk change can be undone.

## Local-only mode
If `NEXT_PUBLIC_SUPABASE_URL` is unset, the app runs fully local: there is no login gate and sync is off. In that mode `/api/ai/*` is allowed only when `NODE_ENV !== 'production'`.

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`

## Performance conventions
- Dexie reads: `liveRows(table)` (`lib/db.ts`) or an index range + `.toArray()`, then filter in JS. Never `table.filter(...).toArray()` / `.each()` / filtered `.count()` over a whole table: those walk a cursor and skip Dexie's live-query cache.
- Sync bookkeeping (`sync_cursors`, `last_sync_at`) lives in the settings row with id `"sync"` (`readSyncMeta`), so a sync never wakes the `getSettings()` live queries. Local writes push only; pulls run on open, focus, online, sign-in, the 5-minute timer and manual sync.
- French sort and search keys are cached by string (`frSortKey`, `normalizeLemma`, `searchHaystack` in `lib/text.ts`); sort with keys computed once per word (`compareFrKeyed`), fold the query once (`searchTerms`).
- The React Compiler is on (`reactCompiler: true`, its Rust port via `experimental.turbopackRustReactCompiler`, so no Babel plugin). `DrawerSheet` (`components/ui/Sheet.tsx`) opts out with `"use no memo"`: compiled, the add sheet's height drifted. Components it skips (try/catch in render paths, e.g. `Desk`, `ReviewScreen`) rely on hand-written `memo`/`useMemo`; keep row props stable (handlers through a ref, as in `WordTable` and `WordList`).
- Lazy chunks: the desktop library (`components/library/lazy-desk.ts`) and the quick-add sheet load on demand through `loadChunk` (`lib/chunk-load.ts`: one retry, then one reload, since the shell HTML is served stale-while-revalidate and a deploy may have removed an older build's chunks).
- `/api/ai/*` is gated only in the route handlers (`guardAiRequest`); `proxy.ts` passes those requests through and refreshes cookies only on page loads.

## Testing
- Vitest unit tests sit next to the code as `*.test.ts`.
- IndexedDB tests use `fake-indexeddb/auto`.
- Playwright e2e lives in `e2e/` at a mobile viewport (390×844), using the preinstalled Chromium (`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`; never run `playwright install`).
- Desktop e2e (`e2e/desktop-*.spec.ts`) runs only in the `desktop-chromium` project (1440×800); everything else runs in `mobile-chromium`.
- Phone ↔ desktop parity: a feature added to one layout is added to the other (DESKTOP-SPEC §8 lists the 2026-10-22 audit); `e2e/desktop-parity.spec.ts` covers the desktop side of each. Theme actions on desktop share `ThemeMenuItems` (`components/library/ThemeActions.tsx`) between the theme page's «⋯» and the sidebar's right-click menu.
- Before pushing: `npm run lint && npm run typecheck && npm test && npm run build`.
