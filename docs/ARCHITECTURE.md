# Карточки для Лизи: architecture and conventions

Read with `docs/plan.md` (scope and phases), `mockups/SPEC.md` (the v3 visual design: tokens, components, copy rules and every screen) and the mockup sources in `mockups/*.dc.html`. The mockups are the visual source of truth: match their layout, spacing, copy and states.

## Stack
- **App:** Next.js 16.4 App Router + Turbopack, React 19.3, TypeScript, Tailwind 4.
  - This Next is newer than most training data. Read `node_modules/next/dist/docs/` before using an API you're unsure of.
  - `cacheComponents: true` is on.
  - Request interception lives in `proxy.ts` (the old `middleware.ts` was renamed).
- **Data:** Dexie 4 (`lib/db.ts`) is the on-device source of truth. The UI reads it with `useLiveQuery` from `dexie-react-hooks`, so screens that use it are client components (`"use client"`).
- **Scheduling:** `ts-fsrs@5`, used only through `lib/scheduler.ts`.
- **Sync and auth:** Supabase (`@supabase/ssr` + `@supabase/supabase-js`).
  - Login is email + password (works inside the iOS home-screen app and needs no custom SMTP); any Supabase account may sign in (sign-up stays off; each account has its own library through RLS), and only the addresses in `ALLOWED_EMAIL` (comma-separated) may use the AI routes. With several addresses in `NEXT_PUBLIC_ALLOWED_EMAIL` the login screen prefills none. Password reset links land on `/auth/confirm` → `/auth/reset`.
  - Sync is last-write-wins on `updated_at` with soft deletes (`deleted_at`). `review_log` rows are only ever soft-deleted (undo).
- **AI:**
  - Packages: `ai@7`, `@ai-sdk/anthropic@4`, `zod@4`.
  - Model `claude-haiku-5-5`; «Точнее» is `claude-sonnet-5-5`. Provider options come from `providerOptionsFor(modelId)` (`lib/ai/model.ts`), chosen by the resolved model id: Haiku gets `thinking: {type:'disabled'}`; Sonnet 5.5 rejects `disabled`, so it gets `thinking: {type:'between_tools'}` with `effort: 'medium'` (faster than its default high, without trimming «Точнее» answers). Keep them fixed per model (a changed effort breaks the prompt cache). Never set temperature/top_p/top_k and never prefill.
  - Use `streamText`/`generateText` with `output: Output.object|array(...)`.
  - Schemas: no `.min/.max/.length`, every field required (use `.nullable()`), confidence is an enum. Limits go in `.describe()` text, and results are sliced on the server.
  - The v7 API changed (`instructions`, `type:'file'` image parts, `Output`). Read the typings in `node_modules/ai` and `node_modules/@ai-sdk/anthropic` before writing calls.
- **PWA:** `app/manifest.ts` + Serwist via `@serwist/turbopack`.

## Product rules
- UI copy is Russian; words are French.
- Never show «ИИ»/«AI», sparkles or "magic" in the UI. The one exception is Settings: the section «ИИ» and its privacy line.
- Settings «ИИ» (device-local, `lib/types.ts` `Settings`): «Автоподсказки при вводе», «Определять уровень сленга», «Подбирать примеры», «Раскладывать по темам автоматически», «Писать заметки», «Вариантов» (1–3), «Регистр вариантов» (сленг / любой / нейтр.), «Модель: подсказки» and «Модель: скриншоты» (Быстрее = Haiku 5.5, Точнее = Sonnet 5.5). Clients send a tier (`model: "fast"|"accurate"`), never a model id; preferences go into the user message, so the system prompts stay frozen.
- Every word has `slang_level` 0..3 (нейтр./fam./arg./vulg.) and a `verlan` flag. Show it with the `SlangMeter` component.
- Dictionary abbreviations (n. m., v. pron., loc., fam., arg., verl.…) explain themselves on a tap with `AbbrHint` (glossary in `lib/abbr.ts`; `SlangMeter hints`) wherever they are not inside another button: the word sheet, the answer side of the review card and the add form's headword.
  - The level, an example and a theme are detected for every new word, not only picked suggestions: `/api/ai/enrich` fills the manual form and «Список» rows before saving (fields the user set by hand, including a chosen theme, are never overwritten), screenshot rows carry an example, and the quick one-line save fills them right after saving (`fillSavedWords`, skipped if the word was edited or undone meanwhile). Each part follows its own switch in Settings «ИИ».
  - Themes follow «Раскладывать по темам автоматически». In the form the pick works like a suggestion's (alternatives, «+ новая тема»). «Список» defaults to «По темам автоматически»: each row goes to its own theme, a new theme only when ≥3 rows share it, low confidence stays in «Входящие». After a quick save the word only moves from «Входящие» into an existing theme, never a new one.
  - «Дополнить карточки» in the library proposes examples for words without one and levels for hand-typed words still at the default, applied only after review, with undo.
- Folders («темы») hold words. `folder_id = null` means «Входящие» (Inbox).
  - Библиотека on phones (layout «C · Под пальцем», chosen 2026-10-22): a ledger strip «158 слов / 23 к повт. / 9 трудных» whose cells are also quick filters, a KPI row under it «120 повторено / 14 сегодня» (`FolderStats.reviewed`: words with a non-new card, paused ones included; words graded since the study day began — `FolderStats.reviewedToday`, counts only, not filters; the desktop subline appends the same «· 120 повторено · 14 сегодня»), a dashed «Входящие · N без темы — Разложить» row while something is unsorted, theme tiles that preview their three newest words, and the search with a «Фильтр и порядок» sheet (status, slang levels, theme, order) pinned at the bottom above the tab bar, riding on the keyboard while typing. Two views, remembered per device (`settings.library_view`): «Темы» (tiles) and «Все слова» (one list, «Показать ещё» per 200). A search or filter always shows the matching words; the order alone does not leave the tiles until «Показать». «Разложить по темам» (when nothing is unsorted), «Дополнить карточки» and the last re-sort's «Отменить» are quiet rows under the tiles. A long press on a theme tile (or Android's / the keyboard's context menu) opens the theme's actions instead of the theme: «Открыть тему», «Повторить тему» (when cards are due), «Тренировка всей темы», «Название, описание и цвет», «Закрепить тему», «Расформировать», «Удалить тему» (with undo) — the same `FolderMenuSheet` as «⋯» on the theme screen.
  - «Тренировка всей темы» (theme menus, and the theme screen's bottom button when nothing is due): `/?folder=<id>&practice=1` opens review straight into a practice round over every card of the theme, shuffled, capped at 200 (`buildPracticeQueue` scope «all»); like the other practice rounds it never writes to the schedule.
  - Buttons that call Claude carry the ink spark glyph (`spark`, `spark-refresh`, `spark-plus` in components/ui/Icons): word refresh, examples ↻ / «+», «Разложить», «Дополнить карточки», «Расформировать», «Распознать заново». Nothing else uses it.
  - Examples: a word has up to 5 (`lib/examples.ts`); the first stays in `example_fr` / `example_ru` (review card, Claude connector, older devices), the rest in `extra_examples` (jsonb, migration `0003_extra_examples.sql`, synced). `ExampleList` (components/examples) shows them with «другой пример» ↻ on each and «+ Ещё пример» under them; both ask `POST /api/ai/example` (card + the examples to avoid → one new sentence, null when nothing new fits). In the word's view they save at once with «Отменить»; in the add form and the edit forms they fill the fields (offline «+» adds an empty example to type). The review card shows the first two.
  - «Изменить карточку» (Повторение; mockups: canvas «Повторение — правка карточки», option A): a pencil on the answer side (and `E`) opens `WordDetailSheet` over the review screen; the card re-reads the word live (`getWord`), so edits show at once, practice rounds included, and nothing is graded. The word's entry form proposes a translation by itself (`components/library/translation-proposal.ts`: `useSuggest` with one answer, no notes, «Вариант … Подставить», never filled without a tap), in the sheet and the desktop pane alike.
  - «На паузу» and «Удалить слово» (Повторение, answer side, before the pencil): the trash soft-deletes the word, the struck bell sets `words.muted` (migration 0009, synced); either takes the card out at once (a practice round drops it, history included) with «Отменить». A muted word stays in the library but `matchWords` (lib/session.ts) leaves it out of every session, practice round and count; library rows say «на паузе», the stats and filters count it apart («На паузе» in the phone filter sheet and the desktop strip, only when there is one), and the word card shows «На паузе — не показывается в повторениях · Вернуть» under «Повторение», «На паузу» among its actions. The connector reads `muted` and sets it with `update_word`.
  - «Тема на паузе»: `folders.muted` (migration 0010, synced) pauses a whole theme — for topics the user will learn later. `isPaused(word, pausedFolderIds)` (lib/core/words.ts) is the one rule: a word is out of review when it or its live theme is muted; `matchWords` takes the paused theme ids from `SessionData`, the library stats, rows («на паузе»), filters and the connector use the same helper. The theme menus have a «На паузе» toggle (`useThemePause`, components/library/theme-pause.ts, with «Отменить»); a paused theme shows «на паузе» on its tile, header and the review picker, its page offers «Вернуть в повторения» instead of review or practice, and its words' cards offer «Вернуть тему». The connector sets it with `update_folder` `muted`, `list_folders` shows it (plus `new` counts per theme) and is told to propose pausing later themes of a sequence, never to do it unasked.
  - «Мои наборы» (Повторение, the «Что повторять» picker; mockups: canvas «Повторение — свой набор», option C): named card sets built from themes (several, «Входящие» included; none = all), word statuses (new / learning / difficult / known), slang levels, age (week / month) and a mode — «По расписанию» (only due + new cards, graded as usual) or «Тренировка» (every card, shuffled, the schedule untouched; picking the set opens straight into the round). Rows of the synced `review_sets` table (migration `0004_review_sets.sql`; soft deletes, last write wins like other rows, so every device sees the same sets; in the JSON backup). Sets stored the old way in `settings.review_sets` move into the table on the Dexie v2 upgrade (`legacyReviewSets`), and old backups are converted on import; the review filter names a set as `set:<id>`; `setSessionFilter` turns a set into a `SessionFilter` (`folderIds`, `slang`, `statuses`, `addedSince`) that `loadSession`, practice rounds and the done screen all honour.
  - «Свои поля» (mockups SPEC/DESKTOP-SPEC «Свои поля»): shared definitions in the synced `field_defs` table, edited in Settings (`components/settings/CustomFieldsSection.tsx`), values on the word in `custom_fields` (`lib/custom-fields.ts`, pure helpers in `lib/core/custom-fields.ts`); filled in the word's view (`components/library/word-fields.ts` + the `fields` part of `word-editor.ts`) and the add form (`WordDraft.customFields`), shown on the review card's answer side (up to 3, `fieldsForDisplay`); deleting a definition leaves its values on the words as one-off fields.
  - «Упражнения» (2nd tab on phones: Повторение · Упражнения · Добавить · Библиотека; on desktop a sidebar/rail item with an ink count of sets not played yet, and `G E`; mockups: SPEC.md and DESKTOP-SPEC «Упражнения», boards `Exercise-*` / `D-Exercise-*`): Duolingo-style sets that Claude writes only through the «Карточки» connector (`exercise_material` to read, then one `create_exercise_set`), never through the app's `/api/ai/*`, so the app spends no tokens and these screens carry no spark glyph; asking for a set means copying a request text into a Claude chat. Rows of two synced tables (migration `0011_exercises.sql`, both in the JSON backup): `exercise_sets` (the content is read-only in the app, which only soft-deletes and restores) and `exercise_runs` (one row per round, upserted after every answer; the outbox coalesces the writes by `${table}:${id}`). A run resumes only on the device that started it (the device-local Dexie table `own_runs`, v6, never synced or backed up), so two devices never write the same run row; another device's interrupted run shows on its tile but a tap starts a new run. Items about words deleted or paused since the set was made are left out when it is played. Item types are `choice`, `cloze`, `register`, `pairs` and `conjugate`; `choice`, `cloze` and `conjugate` carry exactly 3 distractors, for the 2×2 option grid on phone and desktop alike, and the connector checks every set with `validateSet` (`lib/core/exercises.ts`). A `conjugate` item («СПРЯЖЕНИЕ · PASSÉ COMPOSÉ»: the infinitive, then «tu ___») names a verb, a tense and a person; the server writes its form and options from the verb's conjugation (the saved one, else the one built from Lexique, `conjugateDistractors`) when the set is saved, so the player needs no conjugation data. The request builder's «Спряжение глаголов» asks for such a short test (6 / 8 / 10 questions, at most 10 `conjugate` items, no new words; `buildRequestText({ conjugation })` «Сделай упражнение на спряжение глаголов …»; the connector's `exercise_material` `verbs: true`). An item of a type the app does not know is left out when the set is played. Sets play offline from Dexie at `/exercises/play` (no tab bar while playing, back on the done screen; a static route that takes the set from `components/exercises/exercise-request.ts`, else `?set=`, else the newest unfinished run). A tap answers at once, and every answer waits for «Дальше» (no auto-advance since 2026-10-23); a wrong one or «Не знаю» stamps «НЕВЕРНО», requeues the item (`requeue`, up to 3 tries) and waits for «Дальше». Exercises never write `review_state` or `review_log`. New words from the web travel inside the set (`new_words`, with an intro card before their first question) and reach the library only from the done screen, by checkbox («Добавить в библиотеку», `source: "chat"`, with undo). «Чаще в упражнениях» (Settings → «Упражнения»: Обычно / Трудные / К повторению / Трудные и к повторению, and Немного ≥25 % / Половина ≥50 % / Почти все ≥80 % of a set) follows the account in the synced `user_prefs` table (row `exercise_focus`, migration `0012_user_prefs.sql`, in the JSON backup; `lib/user-prefs.ts`, pure helpers in `lib/core/exercise-focus.ts`), so the connector's `exercise_material` applies it even to a plain «сделай упражнение» typed in the chat (focus words first, marked `focus: true`, with the share to meet) and `create_exercise_set` warns `focus_share` when a set falls short. A set can also be made only of the user's difficult words, the words due today, or both, from every theme (`ExerciseSet.scope`, migration `0013_exercise_scope.sql`; `buildRequestText({ scope })` «… по трудным словам из всех тем …», `SCOPE_LABELS`, counts from `useScopeCounts` like the library ledger; the connector's `exercise_material` `only` → `create_exercise_set` `scope`, a shorter set of ≥6 questions when there are few words, no new words).
  - «Контекст» (on phones no tab since 2026-10-23: a 44px magnifier «Контекст» left of the gear in the Library header, and the row when a library search finds nothing; its screen has a back arrow «Библиотека» and the Библиотека tab stays active; on desktop a sidebar/rail item and `G C`; mockups: canvas «Контекст — мокапы», phone layout B «Досье» with A's sense chips): look up any French or Russian word the way Reverso Context does, spending as little on the API as possible. `POST /api/ai/lookup` (Haiku, cheap) answers with the headword, translations by share and synonyms by register. The conjugation is the word's own `conjugation` when the chat saved one through the connector (`words.conjugation`, migration 0008), otherwise built on the device, never by the app's model: rules for regular -er / second-group -ir verbs plus a table of the others built from Lexique 3.83 (`lib/core/conjugate.ts`, `lib/conjugation.ts`, `scripts/build-conjugation.mjs` → `public/lexique/fr-conj.json`). Example sentences come first from Tatoeba (`lib/tatoeba.ts`, its public API asked from the browser, French sentences with a Russian translation, CC BY 2.0 FR, credited under the list) at no cost; the paid web search (`POST /api/ai/context`: Anthropic web search with up to 3 searches, then a structuring call over the cited snippets; the server keeps a sentence only when it is a verbatim part of a snippet the search cited, with that page's URL, `lib/ai/context.ts`) runs only on «Искать ещё в вебе» (or «Искать в вебе» when Tatoeba has nothing). Queries and their results live in the device-local `lookups` table (Dexie v4, never synced or backed up, 50 newest): the history opens offline and a repeat query costs nothing (`lib/context.ts`, «Искать заново» to refresh); each «Недавние» row has «×» (on desktop shown on hover) with «Отменить», and «Очистить» clears them all. Origin visibility: library rows and the review card's answer side show `word.origin` unless Settings → «Оформление» → «Происхождение слов» is off (`settings.origin_visible`, `lib/use-show-origin.ts`). In the word card «+ Поле» asks which field to add: «Происхождение» while the word has none, «Спряжение» for a verb with neither its own nor a dictionary conjugation, and «Своё поле»; an empty origin or conjugation field is not shown (`addableKinds` in `components/library/WordDetailBody.tsx`). Both forms have «Заполнить автоматически» (`components/library/AutoFill.tsx`, `lib/autofill.ts`): the origin from the «Контекст» history when the word was looked up, else `POST /api/ai/fill` (Haiku, one short call, rate bucket `fill`); the conjugation from `/api/ai/fill` only for a verb the dictionary does not conjugate. The note form has the same button and the word-and-translation form has «Определить уровень и часть речи» (slang level, verlan, part of speech); both read the word's own suggestion from `/api/ai/suggest` (`autofillNote`, `detectEntry`). They replace the old «Обновить перевод и заметку». It fills the form; nothing is saved until «Сохранить». Conjugations show through `components/conjugation/ConjugationViews.tsx` (split and per-tense examples in `lib/core/conj-display.ts`): a card per tense on phones, the présent plus a 6 × 4 table dialog on desktop, «Проверь себя» hiding the forms. The add form has the same «+ Поле» (`components/add/DraftExtras.tsx`, draft fields `origin` / `conjugation` / `extraFields` in `components/add/draft.ts`), saved with the new word; a word added from «Контекст» brings the lookup's origin. «Слово по частям» in the word card (desktop: top of the right rail): how the word is made, from Lexique's morphology column on the device («volonté + -aire „относящийся к …“», the root opens in «Контекст»; `scripts/build-morpho.mjs` → `public/lexique/fr-morpho.json`, affix glosses in `lib/core/affixes.ts`, `lib/morpho.ts`), the one-line origin («верлан от lourd», «из арабского kif»: the word's own `origin` when the chat saved one through the connector, else the lookup's), and «Однокоренные» chips. An example goes into the saved word's examples (up to 5) or, for an unsaved word, into the prefilled add sheet; a synonym's «+» opens the add sheet too. Entry points: «Примеры из жизни ›» next to the word's examples, a row under «Варианты» in the add sheet, and a row when a library search finds nothing.
  - «Расформировать» (phone menu, desktop theme menu «Расформировать…»): the classify assign pass picks another existing theme for every word of the theme — hand-placed ones too, since the theme goes away; INBOX or low confidence → «Входящие»; no new themes. The plan (`DisbandSheet`) lets any word be retargeted; applying deletes the theme and moves the words in one transaction (`disbandFolder`), undone with `restoreFolder` (words the user moved since stay put). Without suggestions (offline, error) «Всё во «Входящие»» still works.
  - Automatic sorting never moves a word whose `folder_source = 'user'`, and never renames or deletes a `locked` or user-created folder.
  - A new automatic folder needs ≥3 words.
  - Slang level is never a folder.
- Each word has a review state per direction: `fr_ru`, plus `ru_fr` when `both_directions`.
- «План дня» (mockups: SPEC.md «План дня и уровень языка», canvas rows 22 and 24): the review queue and the day's new words come from one pure function, `planDay` (`lib/core/plan.ts`; no Dexie, no ts-fsrs, no clock: `now`, the study day and the scheduler's `retrievability` are passed in). `loadSession` (lib/session.ts) and the connector's `study_summary` both call it, so the app and Claude count the same day.
  - Start-of-day snapshot: `s0(card)` is the `prev` of the card's first live log of the study day (from 04:00), or the current state when it has none (`dayStartStates`). The snapshot alone decides the budgets, the backlog, the reviews due today, burying and RU→FR unlocks, so the totals hold while studying, an undo (it tombstones the log) rolls them back, and every device agrees once `review_log` has synced. The current state only decides which bucket a card is in.
  - Queue: `[...L-due, ...mix(R, N), ...L-ahead]`. L-due: learning / relearning cards due by now, always first. R: review cards due today in the snapshot and not yet reviewed today, after bury and the cap; normal days by `s0.due`, backlog days by retrievability descending, then difficulty ascending. N: today's new FR→RU words plus unlocked RU→FR cards. `mix` is Anki's intersperse (`intersperse`, `plan.mix = "mixed"`) or reviews first (`"after"`). L-ahead: learning cards due within 20 min (`LEARN_AHEAD_MS`), at the end. Later learning cards are `waiting` (counted in `due`, shown on the wait screen with `nextDue`). Ties break on `fnv1a(dayStart + key)`. The two directions of a word stay 5 positions apart (`spaceSiblings`), and RU→FR is buried to tomorrow when both are due today and neither is overdue; neither rule runs with a direction filter.
  - Cap and budget: `review_cap` counts interday reviews only (logs whose pre-state is Review). More due than the cap = backlog: the excess is `deferred` (schedule untouched) and no new words come. The new-word budget is counted in words, `round(new_words · load · sRate)`: `load` falls from 1 at a 7-day forecast of half the cap to 0 at 80 % of it, and `sRate` = 0.5 when young reviews over 7 days succeed below 80 % (with ≥ 30 of them). `new_words` is a ceiling. The budget is global over unpaused words; the session filter only narrows what is picked. `DayPlan.reason` is `backlog` / `load` / `accuracy` / `empty` / `limit`. «Всё равно добавить новые» (`overrideNewToday`) lifts every throttle up to the ceiling for one study day; it is device-local (the settings row `plan_override` in `lib/user-prefs.ts`: `useNewOverride`, `setNewOverride`), never synced.
  - RU→FR (`plan.ru_fr`): `"after"` (default) unlocks a word's RU→FR once FR→RU is a review card with S ≥ 3 days in the snapshot and has no log today, with its own allowance (`ruLeft`); `"together"` («Назавтра») is the rule before the plan, one limit counted in cards; `"recognition"` never shows RU→FR.
  - New-word order (`plan.new_order`): `"level"` (default; `levelSortKey`: level band up to B2, no level, above B2, plus the register weight; then Lexique frequency, then `created_at`), `"themes"` (theme order, then frequency) or `"added"` (oldest first). Except for `"added"`, themes take turns, at most `themeLimit(budget)` = max(2, ⌈budget/3⌉) new words come from one theme a day, and never two words with the same `searchKey(ru)`.
  - The plan is the synced `user_prefs` row `study_plan` (`lib/core/study-plan.ts`: `StudyPlan`, `DEFAULT_STUDY_PLAN`, `parseStudyPlan`, `studyPlanSummary`; `lib/user-prefs.ts`: `useStudyPlan`, `getStudyPlan`, `setStudyPlan`, modelled on `exercise_focus`). Without a row it comes from the device's `Settings.new_per_day` (cards): `migrateStudyPlan` → `new_words = clamp(ceil(new_per_day / 2), 1, 30)`, the rest the defaults. `new_per_day` stays as that fallback; when it isn't the default, the device saves the migrated plan as the row after a sync's pull (`saveMigratedStudyPlan`), so the connector plans the same day. The e2e fixture seeds the legacy profile (`LEGACY_STUDY_PLAN`: `added`, `after` mix, `together`, no cap), which reproduces the queue before the plan.
- «Уровень языка» (CEFR A1…C2 per word; mockups: SPEC.md «План дня и уровень языка», canvas rows 23 and 24): `effectiveLevel` / `createLevelResolver` (`lib/core/level.ts`, shared with the connector) take the first of: the stored `words.cefr` (`cefr_source` `user` / `chat` / `ai`; migration `0014_word_level.sql`); FLELex-Beacco on the lemma + part of speech (`levelKey`, `levelKeys`); FLELex CRF expressions, exact; the Lexique frequency band (rank ≤ 800 A1, ≤ 2000 A2, ≤ 4000 B1, ≤ 7000 B2, ≤ 12000 C1, else C2, via `Lexique.lookup` in `lib/lexique.ts`); else null («без уровня»). Steps 2–4 are skipped for slang ≥ 2 and verlan (`hasNoEstimate`), and the band also for the made-up slang frequency (`FAKE_SLANG_FREQ`). Estimates are computed, never stored; the UI shows «≈» for every level the user did not set (`levelLabel`). The level orders new words and filters the library; it never gates anything.
  - Data: `scripts/build-cefr.mjs <flelex dir>` builds `public/lexique/fr-cefr.json` (`{v, beacco[6], crf[6]}`: keys per level joined with «|», ≈160 KB raw, ≈63 KB gzipped) from FLELex `Beacco.txt` and `CRF.txt`. FLELex is CC BY-NC-SA 4.0 (François et al. 2014; Beacco levels from Pintard & François 2020), so it stays in its own file with its own section in `public/lexique/LICENSE.txt` and is never merged into the Lexique files (CC BY-SA). `app/sw.ts` precaches it with the rest of `public/lexique`. On the device `loadLevelData` (lib/lexique.ts) fetches it and the Lexique list once; `useLevelData()` (`lib/use-level-data.ts`) shows stored levels only until both are in (`ready`). The connector imports the file statically, as it does `fr-conj.json`.

- «Прогресс» (mockups: SPEC.md «Прогресс», DESKTOP-SPEC §10, canvas rows 32–33; picks D1 A «Ведомость», D2 A): progress is saved by itself, one row per finished study day (04:00 local to 04:00), in the synced table `progress_days` (`ProgressDay` in `lib/types.ts`, id `"YYYY-MM-DD"`, Dexie v8 `"id, updated_at"`, in the JSON backup; migration `0016_progress_days.sql`, which also adds `review_log_user_review_idx`. **Apply 0016 before deploying**: every sync pull reads the table and fails without it). The screen `/progress` (Библиотека tab; phones `ProgressScreen`, from 768 `ProgressDesk`) draws it.
  - What a row holds, in words: `known` («знаю»: `wordStatus` known, every card a review card with stability ≥ 21 d), `learning` («учу»), `fresh` («новых»), `paused` («на паузе», `isPaused`: the word or its live theme muted), `total`, with `difficult` («трудных») a part of `learning`. The buckets don't overlap: a paused word counts only as paused, so known + learning + fresh + paused = total, as in the library stats. `memorized` («помню ≈») = Σ over unpaused words of the mean FSRS retrievability of their cards (a new card 0; fractional days, `forgettingCurve` in `lib/scheduler.ts`). The day's activity: `reviews` (live logs), `again`, `new_introduced` (cards, logs from state New) and `added` (words created). Also `source`, `algo` (`FSRS_ALGO`) and `plan`, the day's kept plan («План и прогресс» below; migration 0017). Finished exercise runs are not stored; the hooks count them from `exercise_runs`.
  - When: `ensureProgressDays` (`lib/progress.ts`) stores every missing day from the first day with data up to yesterday, never today (the screen computes today live). It runs through `saveProgressDays`, which never throws: once after boot (`scheduleProgressDays` in `AppProviders`: 15 s with sync on, so the first pull brings other devices' reviews first, 2 s local-only), after every successful sync pull (`cycle()` in `lib/sync.ts`), and when the screen opens (`useProgress`). With Supabase configured it stores nothing before this device's first full pull (`last_sync_at`) or while a sync cycle runs (`holdingProgressDays` wraps `runSyncCycle`), so a row built from half-pulled data can't win last-write-wins over the good one. Words stamped before 2000-01-02 (the prototype seed, `SEED_TIMESTAMP`) don't start the history.
  - Live vs replay: yesterday is `source: "live"` (current card states, through the log for cards reviewed since). Older gaps are `"replay"`, rebuilt from `review_log` (`replayCounts` in `lib/core/progress.ts`): for each card, the last live log before the day's end gives stability and difficulty, and the state after it is the next log's `prev`, or the current state when there is no later log. A card reset to New counts as new from the reset, a direction turned off leaves from that day, and progress carried over without a log (Anki import) counts from the first log's `prev`. «На паузе» uses the current flags for every past day. Stored rows are added, never rewritten: a day already stored (from any device) stays as it is, even if more reviews for it sync in later. A tombstoned row counts as missing and is written again.
  - Active days, streak: a day is active with ≥ 1 live `review_log` row or a finished exercise run. The calendar and the streak use `activeDayKeys` (`pastActiveDays` checks the log's `review` index keys), not a stored row's `reviews`, because the row may have been stored before another device's reviews synced. `streaks` gives the current and best streak with their dates; a today not yet studied doesn't break it. It is shown only as the one quiet mono line on «Прогресс» (SPEC.md «Прогресс»: never red, never big, no reminders).
  - Screen data: `useProgress(range)` (`"month" | "3m" | "year" | "all"`; from the 1st of this month, 2 or 11 months back, or the first stored day) and `useProgressDay(day)` (the day's numbers, its «Ошибки» and `ordinal`). Reads follow the performance conventions (`liveRows`, index ranges). Pure rules (study days DST-safe, counts, replay, activity, retention, streaks) live in `lib/core/progress.ts`, re-exported by `lib/progress.ts`; the connector uses the clock-free ones.

The copy follows SPEC's rules N1–N6 (a ceiling «до N», no ratio below the plan, study days only, the plan as the subject of a held day, no praise, no banned words, never red).
  - Units are the plan's. New words: distinct `word_id` of FR→RU logs with `state === 0` (`ReviewLog.state` is the state before the answer), every new card with `ru_fr` "together" (`newWordKey`, as `planDay` counts `newToday`). Interday reviews: logs with `state === 2`, what the cap counts. Done counts always come from `review_log` and are never stored. «Прогресс» «Новых слов в день» is `DayPoint.new_words` (`activityByDay({ …, together })`, on every load); `new_introduced` (cards) stays for the opened day. Its dashed line is the current ceiling.
  - Engine: `planFit` (`lib/core/plan-fit.ts`, pure; also `fitLogs`, `newWordsByDay`, `interdayByDay`, `answersByDay`, `isoWeek`). The window is the last 14 study days within 21 calendar days: a study day has a live answer, days off are not data, today counts once its new words are done. Gates (`fit: "warming_up"`, nothing rendered): under 14 days since the first study day, under 7 study days, or under 7 days since the effective `planSince` (the `study_plan` row's `updated_at`, walked back over kept days with the same ceiling and cap, so an undo or a new order doesn't reset it). Otherwise `fits`, `room` or `heavy`. Every number is finite and the result round-trips through JSON.
  - Suggestion: `raise_new` (`room`) needs ≥ 70 % of the plan's study days to take their whole budget, retention ≥ target − 3 pp (≥ 100 answers), no backlog, `forecast7 ≤ 0.6·loadCap` and plan < 30; `to` is the first of +5 / +4 / +3 (≤ 30) with 14·`to` new words left whose 30-day projection stays ≤ 0.5·loadCap, where `planDay`'s load throttle starts (Δ·2.9·d, d 1.5 for "after", 1 otherwise, ±15 % of the increase; the observed reviews per new word once there are 60 days of history). `lower_new` (`heavy`, only when plan > 3, `to = max(3, round(0.6·plan))`): a backlog on ≥ 3 days with `forecast7 > 0.5·loadCap` (a backlog after days away clears by itself), retention < target − 5 pp, or `forecast7 > 0.8·loadCap`; `alt.review_cap` = cap + 50 when the cap was hit on ≥ 3 days and retention is fine. Never a suggestion for studying less (Q2), never a lower cap. Confidence `high` / `medium` / `low`; `low` (5–6 study days) reaches only the connector.
  - Cadence: the synced `user_prefs` key `plan_hint` (`{week, kind, to, dismissed_at}`) freezes the suggestion per ISO week; «Не сейчас» hides that kind for 14 days from its study day (`dayOf`), unless `to` moves by ≥ 30 % or the kind flips.
  - Device side, `lib/plan-fit.ts`: `loadPlanFit` / `usePlanFit` (live logs of 28 days, 56 with ≥ 60 days of history; today's `forecast7`, `backlog`, `available` and `newLeft` from `loadSession`), `rememberSuggestion`, `applySuggestion(fit, "new_words" | "review_cap")` → `{ previous, next }`, `undoSuggestion(previous)` (the snackbar's «Вернуть»: the whole previous plan), `dismissSuggestion`. The plan changes only on a tap. Copy in `components/settings/plan-fit-format.ts` (its test checks N1–N6 over generated states), rows in `PlanFitRows.tsx`.

The override is device-local, so `plan_day` follows the device that wrote last. `plan` is in `REMOTE_COLUMNS` and the backup (missing or junk → null); Dexie needs no new version, and `user_prefs` has no key constraint, so `plan_day` and `plan_hint` need no migration. Migration `0017_progress_days_plan.sql` (`plan jsonb`, nullable). **Apply 0017 before deploying**: new clients push `plan`, and PostgREST rejects the whole `progress_days` push without the column.
  - Connector: `study_summary` always returns `plan_fit` (`lib/mcp/plan-fit.ts`: the same `planFit`, days keyed by `MCP_TIMEZONE`, `plan_hint` read, never written). ## Performance conventions
- Dexie reads: `liveRows(table)` (`lib/db.ts`) or an index range + `.toArray()`, then filter in JS. Never `table.filter(...).toArray()` / `.each()` / filtered `.count()` over a whole table: those walk a cursor and skip Dexie's live-query cache.
- Sync bookkeeping (`sync_cursors`, `last_sync_at`) lives in the settings row with id `"sync"` (`readSyncMeta`), so a sync never wakes the `getSettings()` live queries. Local writes push only; pulls run on open, focus, online, sign-in, the 5-minute timer and manual sync.
- French sort and search keys are cached by string (`frSortKey`, `normalizeLemma`, `searchHaystack` in `lib/text.ts`); sort with keys computed once per word (`compareFrKeyed`), fold the query once (`searchTerms`).
- The React Compiler is on (`reactCompiler: true`, its Rust port via `experimental.turbopackRustReactCompiler`, so no Babel plugin). `DrawerSheet` (`components/ui/Sheet.tsx`) opts out with `"use no memo"`: compiled, the add sheet's height drifted. Components it skips (try/catch in render paths, e.g. `Desk`, `ReviewScreen`) rely on hand-written `memo`/`useMemo`; keep row props stable (handlers through a ref, as in `WordTable` and `WordList`).
- Lazy chunks: the desktop library (`components/library/lazy-desk.ts`) and the quick-add sheet load on demand through `loadChunk` (`lib/chunk-load.ts`: one retry, then one reload, since the shell HTML is served stale-while-revalidate and a deploy may have removed an older build's chunks).
- `/api/ai/*` is gated only in the route handlers (`guardAiRequest`); `proxy.ts` passes those requests through and refreshes cookies only on page loads.
